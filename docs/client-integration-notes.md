# Client integration notes

The client uses the verified backend v0.9.12, pinned template and released shared package. These notes record the implemented integration decisions.

- Run host rules at a monotonic 60 Hz fixed step, with a bounded catch-up budget. Rendering and local settings must not own the simulation clock. Neutralize local controls when focus changes. A stalled host must be visible to guests; never advance the world independently on a guest.
- Publish complete compact snapshots at 20 Hz and transmit guest controls at 20 Hz. The relay permits 50 messages per second per connection, so a 60 Hz input transport would exceed its limit. Local prediction can still run at 60 Hz. Generate ordered input sequences for prediction ticks, retain the unacknowledged tick history, reconcile with host acknowledgements, replay retained movement, and smooth positional corrections across wrapped edges. Flush history on a run change, elimination, or respawn.
- Buffer remote snapshots for approximately 100 ms. Interpolate positions through the shortest wrapped displacement and angles through their shortest angular displacement. Health, lives, fractures, phases, and scores always use authoritative host outcomes.
- Maintain one host simulation while opening settings and while the host spectates. Browser suspension cannot be promised away: show stalled/terminal states honestly, use bounded catch-up on recovery, and document keeping the host tab active. Planned socket replacement must retain this existing world object.
- Render the arena into a fixed 640 × 360 nearest-sampled target, then present it on a DPR-aware canvas. Resize only the presentation surface and pixel-fit scale; logical world bounds remain fixed. Prefer integer display scaling where space permits and document fractional downscaling on small screens.
- Use the template's PixelPerfect2D entry API for game sprites and camera changes. Draw ship headings by selecting pre-rendered directional frames rather than arbitrarily rotating raster artwork. Source the fractional simulation positions from game state, never snapped sprite handles.
- The pinned Babylon Lite 1.32.0 source was inspected directly from its package, rather than assuming another local project's version matches. Its SpriteRenderer derives projection dimensions from `surface.canvas` even when drawing to a texture. Preserve the template's render-target surface-view helper for the fixed logical target and attach the presenter to the real engine surface. The public manual `renderFrame` API permits updating sprite pools immediately before rendering while the independent host timer owns gameplay.
- Keep room entry, roster, lives, wave, count, spectator/results messaging, sharing, and controls in React inside the viewport. Preserve all four template corner roles and gutter layout. Remove orientation settings and shortcuts so the game has one landscape orientation.
- Use browser-tab storage for the private recovery bearer, never a URL or rendered debug output. Sharing exposes only the public room code. Guest retry uses the same identity; actual creator departure ends the invitation. Show admission, capacity, expired-room, initialization, and connection failures visibly.
- Capture actual gameplay evidence only after integration. Protocol browser probes establish transport behavior, not playable-game acceptance. Emulated multi-touch remains distinct from physical mobile hardware verification.
